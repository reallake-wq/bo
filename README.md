# 商机参谋团 OAC

**Opportunity Advisory Crew** 是一个面向销售、售前和业务团队的商机研究与拜访准备系统。它把“我方企业能力”和“目标客户公开信息”结合起来，自动完成主体核对、公开资料检索、证据审计、商机评级、方案建议和拜访问卷生成，帮助团队在第一次拜访前形成一份可行动、可追溯的作战简报。

OAC 的定位不是替代销售判断，也不是自动生成正式投标方案；它更像一组数字参谋，帮助团队快速回答：

- 目标客户是谁，业务和经营状态如何。
- 客户可能有哪些真实痛点和业务压力。
- 我方能力与客户问题之间是否存在可验证切入点。
- 这条商机是否值得投入售前资源。
- 会前、现场和会后分别应该补充哪些关键信息。

## 产品能力

- **我的企业画像**：先定义供给方企业的主营业务和核心产品，再围绕该能力研究目标客户，避免生成脱离我方能力的建议。
- **企业主体核对**：降低集团、子公司、同名企业、招聘页碎片、搜索摘要误匹配等风险。
- **公开资料检索**：覆盖官网、公告、财报、工商、招聘、专利、招投标、新闻、行业线索等来源。
- **证据池机制**：将来源分为高置信、中置信和弱线索，结论尽量绑定网页来源或上传年报页码。
- **敏感信息核验**：法律、信用、股权、财务、重大项目等敏感线索会进入二次核验，未证实内容不会写成确定事实。
- **年报 PDF 解析**：支持上传文字型 PDF 年报，辅助提取营收、利润、现金流、研发投入、员工数量等指标。
- **商机评级**：输出初访前优先级、置信度、投入建议、成立条件、降级信号和资源边界。
- **作战简报**：报告面向手机阅读，优先呈现一句话判断、优先切入、主要风险、下一步动作、解决方案和拜访问卷。
- **拜访轮次闭环**：会后可追加会议纪要、客户反馈或文字附件，生成第二轮/第三轮判断，更新评级、方案和问题清单。
- **任务中心**：后台任务支持进度查看、断点续跑、完成确认和历史报告管理。

## 运行逻辑

```text
选择我的企业
  ↓
输入并核对目标客户
  ↓
创建后台研究任务
  ↓
检索规划：主体、工商本地、经营财务、产品客户、数字化 AI、痛点机会
  ↓
公开资料检索与网页读取
  ↓
来源清洗、证据分级、敏感信息核验
  ↓
模型综合分析：客户画像、痛点机会、方案建议、评级和问卷
  ↓
生成并保存作战简报
  ↓
会后追加反馈，形成下一轮分析
```

## 技术结构

- **前端**：Vite + TypeScript，移动端优先的单页应用。
- **后端**：Netlify Functions，负责主体核对、任务创建、报告生成、报告检索和轮次追加。
- **存储**：本地开发使用 `local-data/`；线上使用 Netlify Blobs 保存报告、任务、画像和索引。
- **模型**：通过 DeepSeek 官方 API 调用 Flash/Pro 模型。模型负责检索规划和综合分析，不直接作为事实来源。
- **搜索与阅读**：搜索 API 和网页读取能力负责收集候选资料，所有正文判断尽量绑定可追溯来源。

## 本地运行

复制环境变量模板：

```powershell
copy .env.example .env
notepad .env
```

安装依赖并启动：

```powershell
npm install
start-local.cmd
```

打开本地地址：

```text
http://localhost:9891
```

停止本地服务：

```powershell
stop-local.cmd
```

## 环境变量

本地使用 `.env`，线上在 Netlify 项目后台配置同名环境变量。不要把真实密钥提交到仓库。

```text
DEEPSEEK_API_KEY=
DEEPSEEK_API_BASE_URL=https://api.deepseek.com
DEEPSEEK_RESEARCH_MODELS=deepseek-v4-flash,deepseek-v4-pro
DEEPSEEK_THINKING_MODE=disabled

TAVILY_API_KEYS=
JINA_API_KEY=
```

说明：

- `DEEPSEEK_API_KEY` 为必填。
- `TAVILY_API_KEYS` 可配置多个 Key，用英文逗号或换行分隔，用于提高搜索稳定性。
- `JINA_API_KEY` 可选，用于增强网页读取能力。
- `.env`、`local-data/`、日志和构建产物已在 `.gitignore` 中排除。

## 部署到 Netlify

项目已包含 `netlify.toml`：

```toml
[build]
  command = "npm run build"
  publish = "dist"
  functions = "netlify/functions"
```

部署前请先本地检查：

```powershell
npm run build
```

线上站点需要在 Netlify 中配置必要环境变量。报告数据不会随 GitHub 代码自动同步；如需迁移本地演示报告，应通过 Netlify Blobs 或专门的数据同步脚本导入。

## 使用流程

1. 在“我的企业”中创建或选择供给方企业画像。
2. 在“创建”中输入目标客户名称，必要时补充行业、地区、已知需求或年报。
3. 从候选主体中确认正确客户。
4. 创建任务后可关闭页面，稍后在“任务中心”查看进度。
5. 报告生成后，在“报告”中打开作战简报。
6. 拜访后可追加会议纪要、录音转写文字或客户反馈，生成下一轮判断。

## 边界说明

- 报告适合会前研究、初访判断和售前资源分配，不等同于法律、财务或投资尽调报告。
- 未能公开证实的信息会作为线索或待核验问题处理，不应直接作为确定结论使用。
- 年报 PDF 仅支持文字型 PDF；扫描件需要 OCR 后再处理。
- 模型输出需要结合业务经验复核，尤其是预算、付款、决策链、法律风险和重大项目线索。
